# Reword

Change expression, not the promise. A six-word request should yield a small edit and a clear diff, not a document redesign.

1. Read [the method](references/method.md). Establish the exact current target and whether the user authorized an edit or wants proposed wording. Use existing instructions without requiring an interview or style setup. If the selection is ambiguous, ask which occurrence before changing text.
2. Identify the target's commitments, qualifiers, exact terms, and protected spans. Read surrounding text for context; context is not an editable target. The inventory is complete when every claim and limiting condition has a before/after counterpart.
3. Reword only the authorized text. Keep protected content exact. When better wording would require changing a fact, removing a condition, or editing a neighboring sentence, explain that conflict rather than expanding scope.
4. Compare the result with the base text using the checks in the method. Show the changed passage or diff. Distinguish the mechanical boundary check from editorial assessment of meaning; identify any unrun check. Return the authorized edit or proposal, not a dashboard unless requested.

Use [the contrasting examples](references/examples.md) when deciding whether a request is rewording, substantive revision, or condensation. Stop with a targeted question when the requested wording changes a commitment the user also asked to preserve.

Record this output in `docs/plans/` per the [doc system](../../references/doc-system.md), delegating the write to a subagent.
