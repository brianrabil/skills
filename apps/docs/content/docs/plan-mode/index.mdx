---
title: Plan Mode
description: Thirty-five focused skills for inquiry, decisions, planning, review, and follow-through.
---

Plan Mode is a collection of 35 standalone Markdown skills. Choose the operation
that matches the work in front of you; there is no required sequence or runtime
package to install.

```bash
npx skills add brianrabil/skills --full-depth --skill plan-mode-research
```

## Understand the problem

| Skill                     | Use it when                                               | Result                                    |
| ------------------------- | --------------------------------------------------------- | ----------------------------------------- |
| `plan-mode-clarify`       | Ambiguity changes the next step                           | Focused questions or explicit assumptions |
| `plan-mode-explore`       | You need viable paths before choosing                     | Options, tradeoffs, and the next decision |
| `plan-mode-research`      | One bounded question needs evidence                       | A sourced answer with limits              |
| `plan-mode-deep-research` | Several contested claims determine a consequential choice | A claim-to-source map and conclusion      |
| `plan-mode-read-docs`     | You need a current API or tool contract                   | Version-matched behavior and limits       |
| `plan-mode-archaeology`   | History, not current code, explains a regression          | The change, timing, and rationale         |
| `plan-mode-trace`         | One value must be followed end to end                     | A concrete path through the system        |
| `plan-mode-calibrate`     | A decision depends on how certain a claim is              | Evidence, confidence, and the next check  |

## Decide and communicate

| Skill                  | Use it when                                         | Result                                     |
| ---------------------- | --------------------------------------------------- | ------------------------------------------ |
| `plan-mode-brainstorm` | You want distinct possibilities before selection    | Ideas with costs and probes                |
| `plan-mode-reframe`    | The current question blocks progress                | Alternative frames and changed assumptions |
| `plan-mode-debate`     | A proposal needs its strongest case and countercase | Arguments and the decision hinge           |
| `plan-mode-counsel`    | A choice has competing priorities                   | A recommendation and reversal conditions   |
| `plan-mode-decide`     | Viable options need closure                         | A decision record                          |
| `plan-mode-prioritize` | Work exceeds real capacity                          | An ordered queue with rationale            |
| `plan-mode-estimate`   | Work needs a size, date, or confidence              | A range and named unknowns                 |
| `plan-mode-bounds`     | Limits may invalidate the route                     | Hard constraints and remaining room        |
| `plan-mode-premortem`  | A plan needs failure analysis                       | Causes, signals, and mitigations           |
| `plan-mode-sunset`     | A goal may no longer be worth pursuing              | A stop-or-continue recommendation          |
| `plan-mode-park`       | Deferred work must remain discoverable              | A durable parked-item record               |
| `plan-mode-teach`      | You want to understand and apply a concept          | An explanation, example, and boundary      |
| `plan-mode-visualize`  | A relationship or sequence is hard to see           | A fitting diagram, table, or timeline      |

## Produce and review artifacts

| Skill                    | Use it when                                     | Result                                      |
| ------------------------ | ----------------------------------------------- | ------------------------------------------- |
| `plan-mode-to-prd`       | Product outcomes need observable requirements   | A product requirements document             |
| `plan-mode-to-spec`      | Agreed behavior needs technical contracts       | A testable implementation specification     |
| `plan-mode-to-epic`      | One outcome spans coordinated workstreams       | An epic with dependencies and a finish line |
| `plan-mode-to-tickets`   | Accepted work needs executable slices           | Ticket drafts with acceptance and blockers  |
| `plan-mode-to-checklist` | An accepted plan needs an execution surface     | An ordered checklist with evidence fields   |
| `plan-mode-brief`        | Research needs a decision-ready handoff         | A concise brief                             |
| `plan-mode-handoff`      | Another session or agent must resume the work   | A portable state summary                    |
| `plan-mode-docs`         | Plan artifacts need recording or reconciliation | A current `docs/plans/` tree                |
| `plan-mode-audit`        | An artifact must meet a named standard          | Evidence-backed findings                    |
| `plan-mode-spec-lint`    | A specification may leave behavior unstated     | Ranked gaps and proposed clarifications     |

## Carry the work through

| Skill               | Use it when                                    | Result                               |
| ------------------- | ---------------------------------------------- | ------------------------------------ |
| `plan-mode-plan`    | The goal needs an actionable route             | Ordered steps and acceptance checks  |
| `plan-mode-run`     | An accepted plan needs execution or resumption | Progress backed by completed checks  |
| `plan-mode-verify`  | You need to know whether the outcome works     | Evidence per acceptance criterion    |
| `plan-mode-reroute` | A route fails or becomes stale                 | Revised steps that preserve the goal |

The imported `plan-*` skills are a separate collection.
